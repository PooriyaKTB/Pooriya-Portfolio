Approach

The sequence I don't skip

Buildings and software tend to fail for the same reason: someone jumped straight to building. This is the sequence either way.

01 02 03 04

Discover

Understand who's using this and why, before drawing anything — user interviews, desk research, competitor analysis.

Define

Turn research into a scope someone can sign off on. This is where ambiguity has to end.

Build

Execute against real constraints — budget, timeline, legacy code. Clean, tested, built to hold up.

Deliver

Ship it, then defend it — to inspectors, code reviewers, or judges at Google London.
